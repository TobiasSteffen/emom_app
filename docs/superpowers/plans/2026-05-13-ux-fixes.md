# UX Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix three post-launch UX issues: plan library tap behaviour (activate only, chevron opens editor), settings back button navigation and immediate persistence, and Android Auto Backup for history/settings survival across reinstalls.

**Architecture:** All changes are isolated to existing files — no new providers or models. ConfigScreen gains an `onBack` callback that WorkoutScreen wires to its `PageController`. PlanLibraryScreen splits activate/edit into two gesture targets. AndroidManifest gains backup attributes; the two XML rule files already exist on disk.

**Tech Stack:** Flutter/Dart, Riverpod 2.x (`@riverpod` code-gen), SharedPreferences, `path_provider`, Android Manifest XML.

### Task 2: ConfigScreen back button + immediate settings save

**Files:**
- Modify: `lib/features/config/config_screen.dart`
- Modify: `lib/features/workout/workout_screen.dart:205`

**Context:**  
`ConfigScreen` is embedded as page 1 of a `PageView` in `WorkoutScreen` — it is NOT pushed onto the Navigator stack. The AppBar back arrow currently calls `_save()` (replaces state in memory) but does NOT navigate back. Fix: add `VoidCallback? onBack` to `ConfigScreen`; the back button calls `_save()` then `widget.onBack?.call()`. `WorkoutScreen` passes a callback that animates the `PageController` back to page 0.

Additionally, `_save()` should persist to SharedPreferences immediately (currently it only updates in-memory state; disk write happens only when `WorkoutScreen.onPageChanged` fires). Fix: call `ref.read(settingsNotifierProvider.notifier).save()` inside `_save()`. Also call `_save()` from `FeedbackTab.onChanged` so every toggle/slider persists immediately.

`SettingsNotifier.save()` is `Future<void>` — call it without `await` (fire-and-forget) since we don't need to block the UI.

- [ ] **Step 1: Update `ConfigScreen` — add `onBack`, fix `_save()`, fix `onChanged`**

Replace the entire content of `lib/features/config/config_screen.dart`:

```dart
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';
import '../../core/models/settings.dart';
import '../../core/providers/settings_provider.dart';
import 'widgets/feedback_tab.dart';

class ConfigScreen extends ConsumerStatefulWidget {
  final int visitCount;
  final VoidCallback? onBack;
  const ConfigScreen({super.key, this.visitCount = 0, this.onBack});

  @override
  ConsumerState<ConfigScreen> createState() => _ConfigScreenState();
}

class _ConfigScreenState extends ConsumerState<ConfigScreen> {
  late AppSettings _s;

  @override
  void initState() {
    super.initState();
    _s = ref.read(settingsNotifierProvider).requireValue;
  }

  @override
  void didUpdateWidget(ConfigScreen old) {
    super.didUpdateWidget(old);
    if (old.visitCount != widget.visitCount) {
      _s = ref.read(settingsNotifierProvider).requireValue;
    }
  }

  void _save() {
    ref.read(settingsNotifierProvider.notifier).replace(_s);
    ref.read(settingsNotifierProvider.notifier).save();
  }

  @override
  Widget build(BuildContext context) {
    final settingsAsync = ref.watch(settingsNotifierProvider);
    if (settingsAsync.valueOrNull == null) return const SizedBox();
    return Scaffold(
      backgroundColor: const Color(0xFF000000),
      appBar: AppBar(
        backgroundColor: const Color(0xFF000000),
        elevation: 0,
        leading: IconButton(
          icon: const Icon(Icons.arrow_back, color: Colors.white38),
          onPressed: () {
            _save();
            widget.onBack?.call();
          },
        ),
        title: const Text(
          'EINSTELLUNGEN',
          style: TextStyle(fontSize: 15, letterSpacing: 4, color: Colors.white38),
        ),
      ),
      body: ListView(
        padding: const EdgeInsets.fromLTRB(24, 16, 24, 40),
        children: [
          FeedbackTab(
            settings: _s,
            onChanged: () {
              setState(() {});
              _save();
            },
          ),
        ],
      ),
    );
  }
}
```

### Task 3: Android Auto Backup

**Files:**
- Modify: `android/app/src/main/AndroidManifest.xml`
- Commit (already exist): `android/app/src/main/res/xml/backup_rules.xml`
- Commit (already exist): `android/app/src/main/res/xml/data_extraction_rules.xml`

**Context:**  
The two XML rule files already exist on disk (untracked). `backup_rules.xml` covers pre-API-31 full backup (SharedPreferences + files). `data_extraction_rules.xml` covers API 31+ cloud backup and device-to-device transfer (same domains). The `<application>` tag in `AndroidManifest.xml` needs three new attributes to enable Android Auto Backup.

There is no unit test for a manifest change. Verify with `flutter analyze`.

- [ ] **Step 1: Verify the XML files are correct**

Read `android/app/src/main/res/xml/backup_rules.xml`. It should contain:

```xml
<?xml version="1.0" encoding="utf-8"?>
<full-backup-content>
    <include domain="sharedpref" path="."/>
    <include domain="file" path="."/>
</full-backup-content>
```

Read `android/app/src/main/res/xml/data_extraction_rules.xml`. It should contain:

```xml
<?xml version="1.0" encoding="utf-8"?>
<data-extraction-rules>
    <cloud-backup>
        <include domain="sharedpref" path="."/>
        <include domain="file" path="."/>
    </cloud-backup>
    <device-transfer>
        <include domain="sharedpref" path="."/>
        <include domain="file" path="."/>
    </device-transfer>
</data-extraction-rules>
```

If either file is missing or wrong, create/fix it before proceeding.

- [ ] **Step 2: Add backup attributes to AndroidManifest**

In `android/app/src/main/AndroidManifest.xml`, find the `<application` opening tag:

```xml
    <application
        android:label="emom_app"
        android:name="${applicationName}"
        android:icon="@mipmap/ic_launcher">
```

Replace it with:

```xml
    <application
        android:label="emom_app"
        android:name="${applicationName}"
        android:icon="@mipmap/ic_launcher"
        android:allowBackup="true"
        android:fullBackupContent="@xml/backup_rules"
        android:dataExtractionRules="@xml/data_extraction_rules">
```
